# alex-linde — Personal Portfolio · Claude Config

> Inherits global values from ~/.claude/CLAUDE.md

Static single-page portfolio for Aleks Linde (alekslinde.com). Signature feature: a **human ↔ robot mode toggle** that swaps every piece of copy on the page (name, tagline, project list, contact labels, footer) between a warm "human" voice and a machine-readable "robot" voice.

---

## Project Context

**Stack:** Astro 7 (static output, no framework runtime — vanilla TS + `.astro` components)
**Package manager:** npm
**Primary language:** TypeScript
**Styling:** SCSS (Sass), autoprefixer via PostCSS
**Testing:** Vitest (jsdom env) + Playwright available
**Deploy:** GitHub Pages via `.github/workflows/deploy.yml` (auto-deploys on push to `main`)

There is **no React**. Interactivity is plain TS modules loaded via `<script>` in `.astro` pages.

---

## Project Structure

```
src/
  content.ts            ← ALL site copy lives here (COPY.human / COPY.robot). Edit here, not in markup.
  content.test.ts       ← Tests for the copy shape
  pages/index.astro     ← The only page; wires components + boots ModeController
  layouts/Base.astro    ← HTML shell / <head>
  components/
    *.astro             ← Markup: Name, Tagline, Projects, Contact, ModeSwitcher
    ModeController.ts    ← Core logic: swaps DOM text between human/robot modes
    PixelRipple.ts / PixelRain.ts / RobotAnimation.ts ← Canvas/pixel effects
    *.test.ts            ← Unit tests colocated with the module they cover
  styles/
    global.scss          ← Entry; @use's the partials below
    partials/_*.scss     ← One partial per section (_tokens, _name, _projects, …)
public/                  ← Static assets served as-is (favicon, og.png, robots.txt, sitemap.xml)
```

## Content & Copy Reuse

- **All user-facing text is in `src/content.ts`** as the `COPY` object with `human` and `robot` variants. To change wording, projects, or contact labels, edit this file — never hardcode strings in `.astro` markup.
- Both `COPY.human` and `COPY.robot` must stay structurally identical (same keys, same number of projects). `ModeController` and `index.astro` index into them by position — adding a project means adding it to **both** variants.
- `ModeCopy` type is derived from `COPY.human`; keep it in sync.

## Component & Code Reuse

- Check `src/components/` before building anything new; extend existing components first.
- New `.astro` components → `src/components/`. Pure logic/effects → `.ts` siblings.
- Colocate tests as `<Name>.test.ts` next to the module.
- Effects (pixel/canvas animations) are standalone TS classes — reuse their pattern rather than adding a dependency.

---

## Stack Conventions

- Astro components (`.astro`) for markup; frontmatter for props, no client JS unless needed.
- Client behavior via `<script>` importing a TS module (see `index.astro` → `ModeController`).
- Styling in SCSS partials under `src/styles/partials/`, composed in `global.scss` via `@use`. Design tokens live in `_tokens.scss`.
- Keep it static — no server, no runtime framework. `output: 'static'` in `astro.config.mjs`.
- Accessibility matters here: skip-link, `_a11y.scss` partial. Preserve it.

## Off Limits

- Don't edit `dist/` — it's the build output (gitignored, regenerated by `npm run build`).
- Don't hand-edit `package-lock.json`.

## Commands to Know
